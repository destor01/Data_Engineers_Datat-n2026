Hosting is the hidden cost on the cloud path. Audio is never deleted from Supabase Storage. The free tier's 1 GB holds only about 17–35 hours of MP3, so it fills after roughly 20–35 interviews. Other checks

  • Secrets in git: .env is git-ignored and was never committed; only .env.example (empty values) is tracked.
  • Injection: ffmpeg/ffprobe run with argument lists (no shell=True). Upload filenames are reduced to a safe basename (../../../evil.txt was stored as evil.txt). The React UI never uses dangerouslySetInnerHTML, so transcript text is escaped.
  • Supabase: RLS is enabled on all three tables with no anon policies, and the bucket is private. The service-role key is only used server-side.
  • npm audit: 2 advisories in vite 5.4.21 / esbuild 0.21.5. They affect only the npm run dev server, not the built dist/. The fix is a major Vite upgrade, so I didn't apply it.
  • Python CVE scan: pip-audit couldn't run here (the sandbox blocked the download). The installed versions are current: fastapi 0.165, starlette 1.10, python-multipart 0.0.34, requests 2.34.2, urllib3 2.8.

What the stress test surfaced

  1. The local store slows down as history grows. After about 200 jobs, .local_data/store.json was 5.86 MB, and every write rewrites the whole file under one global lock (276 ms per write). It grows about 30 KB per evaluated interview, so past roughly 1,000 interviews every action takes over a second. Use Supabase, prune old jobs, or drop indent=2 (about 30% smaller) before that.
  2. /api/status is the slowest read (p95 around 0.7–1.1 s at 30 concurrent requests) because it probes the GPU and ffmpeg on every call. Cache it if many people keep the page open.
  3. Vercel's 60 s limit: evaluation runs inside the request. A 2-hour interview is about 10 JEV requests in three waves of 4, which fits if OpenRouter answers each in under ~15 s. Deepgram's URL mode waits synchronously (58 s timeout), so 2-hour audio can time out on Vercel. Prefer AssemblyAI there, since it polls asynchronously.
  4. Evaluation is CPU-bound locally at about 3.4 mock evaluations/s with 10 concurrent. Real throughput is set by OpenRouter latency.

4 · What you need to do

  1. Before any deployment, set APP_PASSWORD to a long random value (Vercel → Settings → Environment Variables). Without it the deployed API returns 503. Basic auth has no lockout, so length is the protection.
  2. Add "speech_model" to the AssemblyAI request in app/cloud_stt.py so you're billed the Universal-2 rate ($0.17/h) instead of whatever the account default is.
  3. Delete audio from Supabase Storage after transcription, or budget for Supabase Pro.
  4. Data protection: ENCOVI interviews are household data. The cloud path sends audio to AssemblyAI or Deepgram, and every path sends transcript text to OpenRouter/TypeSafe (US processors). Local WhisperX keeps the audio on-site. Check this against INE's data-handling rules.
  5. Optional: upgrade Vite to clear the dev-server advisories, and delete the legacy static/ UI.
